# `data/` — the content contract

Everything under `data/` is authored content, kept separate from `src/` engine code so
the same files can drive the web preview, `tools/data-to-json.mjs` (real JSON, for Unity
later), and any future authoring tool.

## The contract

- **One `export default {...}` per file.** No named exports, no side effects.
- **JSON-literal shape only.** Numbers, strings, booleans, `null`, arrays, and plain
  object literals. **No functions, no `import`, no computed/spread values, no
  `Math.PI`-style expressions** — anything that isn't valid JSON once evaluated breaks
  `tools/data-to-json.mjs`, which needs to read these as data, not run them as code.
- **Kept as `.data.js`, not `.json`.** A plain `import` needs no fetch and behaves
  identically on Cloudflare Pages and under any wrapper/mount scheme — the same reasoning
  as `ASSET_BASE` in `src/scenes-data.js`. `tools/data-to-json.mjs` is what produces real
  `.json` files, and only for consumers that need them (Unity's importer).

## Layout (grows as Phase 0 tasks land)

```
data/
  README.md              # this file
  weapons.data.js         # P0.2
  enemies.data.js         # P0.2 (score) + P0.3 (enemy types)
  waves/<setId>.data.js    # P0.3 — named sets, not one global array
  scenes/<slug>.data.js    # P0.4
  campaign.data.js        # P0.5
  missions/<id>.data.js    # P0.7
  objectives.schema.md    # P0.7 — the 11-type objective vocabulary, a hard cap
  json/                   # generated by tools/data-to-json.mjs — gitignored? no,
                           # committed, so Unity can pull it without running Node
```

## Validating

```
node tools/data-to-json.mjs --check    # exits 0 if every data/*.data.js file is
                                        # valid-shape and json/ is up to date
node tools/data-to-json.mjs            # (re)generate data/json/*.json
```
